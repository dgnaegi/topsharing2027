# Accessibility

Checkliste für Accessibility-Reviews dieses Projekts. Ziel ist WCAG 2.1 AA.

## Grundsatz

Barrierefreiheit ist kein Nachtrag. Neue Komponenten übernehmen die Muster, die schon im Code
stehen (globaler Fokus-Ring in `GlobalStyle.ts`, `prefers-reduced-motion`, Fieldset/Legend für
Checkbox-Gruppen), statt eigene Lösungen zu erfinden.

## Semantik & Struktur

- [ ] Jede Seite hat genau ein `h1`, danach `h2`/`h3` ohne Sprünge in der Hierarchie
- [ ] Landmarks sind korrekt gesetzt: ein `header`, ein `main`, ein `footer`, `nav` nur für
      echte Navigation
- [ ] `<main id="main-content" tabIndex={-1}>` ist auf jeder Route vorhanden, `SkipLink`
      (`components/SkipLink.tsx`) springt dorthin
- [ ] Interaktive Elemente sind das passende HTML-Element (`button` für Aktionen, `a` nur für
      Navigation), nie ein `div` mit `onClick`

## Tastatur

- [ ] Jede Aktion ist ohne Maus erreichbar und auslösbar
- [ ] `:focus-visible` bleibt sichtbar, kein `outline: none` ohne Ersatz
- [ ] Keine Tastaturfallen: Tab kommt aus jedem Bereich wieder heraus
- [ ] Dialoge fangen den Fokus (`hooks/useFocusTrap.ts`), setzen ihn beim Öffnen auf das erste
      fokussierbare Element und geben ihn beim Schliessen an das auslösende Element zurück

## Formulare

- [ ] Jedes `Input`/`TextArea`/`FileInput` hat ein `Label` mit passendem `htmlFor`/`id`
- [ ] Fehlermeldungen haben eine eigene `id` und sind per `aria-describedby` mit dem Feld
      verknüpft, das Feld trägt zusätzlich `aria-invalid`
- [ ] Checkbox-Gruppen stehen in `fieldset`/`legend` (siehe `SupportChoice.tsx`)
- [ ] Fehlermeldungen folgen [MICROCOPY.md](./MICROCOPY.md): ganze Sätze, freundliche Bitte,
      keine Stichworte
- [ ] Asynchrone Rückmeldungen nach dem Absenden stehen in einer Live-Region (`role="status"`
      für Erfolg, `role="alert"` für Fehler), nicht nur visuell im DOM

## Dialoge & dynamische Inhalte

- [ ] `role="dialog"` und `aria-modal="true"`, dazu `aria-labelledby` auf den Titel im Dialog
- [ ] Escape schliesst den Dialog, ein Klick auf das Overlay ebenfalls
- [ ] Der Fokus ist während der Dialog offen ist auf ihn beschränkt (kein Tab in den
      Hintergrund)

## Bilder

- [ ] `alt` beschreibt den Inhalt, nie den Dateinamen. Rein dekorative Bilder bekommen `alt=""`
- [ ] `width`/`height` sind gesetzt, damit nichts beim Laden springt

## Farbe & Kontrast

- [ ] Text erreicht mindestens 4,5:1 Kontrast zum Hintergrund (normale Textgrösse)
- [ ] Zustände (Fehler, aktiv, unterstützt) werden nie nur über Farbe kommuniziert, immer
      zusätzlich über Text, Symbol oder Unterstreichung (siehe `QuoteTrigger`)

## Testen

- [ ] Ganze Seite einmal nur mit Tab, Shift+Tab, Enter, Escape bedienen
- [ ] Stichprobe mit VoiceOver (macOS) oder NVDA (Windows) auf neuen Komponenten
- [ ] `axe DevTools` oder Lighthouse-Accessibility-Audit vor dem Merge ohne kritische Befunde
